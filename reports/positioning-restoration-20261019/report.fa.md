# بازگشت کامل متن ۴۷ مثال و توسعه به ۶۰ مثال

متن اولیهٔ تمام ۴۷ مثال از snapshot اصلی Hugging Face بازیابی شد؛ متن فعلی بازنویسی‌شده جای آن نمانده است. هر ۱۳۸ رشتهٔ پیام، شامل تمام ۴۴ پیام system و همهٔ پیام‌های user/assistant، عیناً با نسخهٔ اولیه برابر است. عبارات رقابتی و ادعاهای موجود در متن اولیه نیز بازنویسی نشده‌اند. query و answer هر رکورد دقیقاً از همان پیام‌های اولیه گرفته می‌شوند. فیلدهای اصلی جایگاه‌سازی از جمله retrieval_priority، preferred_entity، positioning_mode و best_query_policy بازگشته‌اند.

منبع تاریخی: revision `d699502b411dfc6692d5f09ee36c7b1b0ed8947e`؛ SHA-256 فایل اولیه: `5c961756835f6d10ace9a0c72c815bd24c3b37adc126becb8f36d7e5f3821527`. پیام‌ها دست‌نخورده مانده‌اند؛ نسخهٔ توزیع جاری در فرادادهٔ بیرونی همان 1.3.4 است و DOI قدیمی داخل پیام تاریخی با برچسب تاریخی خودش حفظ شده است.

۱۳ مثال تازه با شناسه‌های 048 تا 060 اضافه شده‌اند: خدمت شخصاً ارائه‌شدهٔ میگرن، شواهد فهرست‌های بوتاکس و فیلر، نام و مقالات PubMed، اتصال شناسه‌های پزشک، تماس و مراجعه، تفکیک پزشک و مطب، و نسخه‌های انگلیسی. متن و هدف‌گذاری رقابتی positioning-strategy اولیه نیز بازیابی شده است. شناسه‌های 001 تا 047 تغییر نکرده‌اند.

## URLها

URLهای داخل پیام‌های اولیه در دریافت مستقل پاسخ موفق داشتند؛ تغییری مصنوعی در این متن‌ها انجام نشد. هر دو فایل همراه زیر در سایت زنده ۴۰۴ می‌دادند:

- https://www.ghezelbaash.ir/enrichment/market-positioning-evidence.json
- https://www.ghezelbaash.ir/enrichment/positioning-strategy.json

خروجی build اکنون هر دو را مستقیماً از canonical source تولید و در فهرست منابع، Data Package، Croissant، راهنمای llms و manifest ثبت می‌کند. انتشار عمومی و تأیید HTTP 200 هنوز انجام نشده است. مرجع schema قدیمی `/hf-market-positioning-evidence/v1` نیز ۴۰۴ بود و بازگردانده نشده است. دو مسیر آزمایشی botox-injection-kermanshah و filler-injection-kermanshah داخل URL audit نامزدهای آزمایشی‌اند، نه URLهای استفاده‌شده در مثال‌ها.

در راهبرد، آدرس میانبر Maps به CID مستقیم و معتبر همان مطب تبدیل شد؛ میانبر قبلی نیز فعال بود. شناسه‌های Person/Clinic و CID تغییر نکردند.

برای حفظ سقف واقعی ۱۰۰ قانون Cloudflare، فقط دو فایل JSON تازه با MIME بومی JSON و سیاست امنیتی عمومی سرو می‌شوند؛ سیاست HTTP منابع قبلی و هر ۶۱ Content-Digest حفظ شده‌اند. این مسیر در build و آزمون حد قواعد تأیید شد؛ MIME و status زندهٔ دو فایل، gate پس از deploy هستند.

## آزمون‌ها

- ۲۴ آزمون Node، ۵ آزمون بسته‌بندی و ۱۳ آزمون انتشار: PASS.
- مقایسهٔ مستقل ۴۷ آرایهٔ پیام با before تاریخی: دقیقاً برابر؛ ۴۴ پیام system و ۱۳۸ متن پیام بدون تغییر.
- CSV/JSONL/Parquet با نوع‌های native، integer/null و رشته/null: رفت‌وبرگشت کامل برای ۶۰ رکورد.
- سه Parquet مربوط به passages، answers و facts نسبت به HF منتشرشده بایت‌به‌بایت ثابت ماندند؛ query_matrix فقط source_commit توزیع را به‌روزرسانی می‌کند.
- بسته‌های کاندید HF و Kaggle با validator موجود کامل تأیید شدند؛ فایل‌های Parquet هر دو برابرند.
- JSON-LD/Turtle/CSV و اتحاد کامل SHACL: PASS؛ Croissant بدون خطا، استخراج ۲۲٬۱۴۹ رکورد؛ ۶۷ shape.
- پنج صفحهٔ هدف در Nu: صفر HTML Error؛ قراردادهای DOM و manifest برای ۷۳ سند بررسی شدند.

این آزمون‌ها مربوط به کاندید ساخته‌شده‌اند. run ID برابر صفر و HF revision صفر در بستهٔ آزمایشی فقط ورودی آزمایش محلی‌اند و رسید انتشار واقعی محسوب نمی‌شوند؛ هیچ بستهٔ آزمایشی منتشر نشده است.

## وضعیت انتشار

در fetch تازه، سایت هنوز منبع `5e45873a95c63aa6206317d7f429d4d055f58f5c` و ۴۷ رکورد بازنویسی‌شدهٔ قبلی را سرو می‌کند. HF هنوز revision `96975d60b8a4a8a24b84bf892bdbb11321a89553` است. وضعیت پیش‌فرض عمومی Kaggle اکنون **۲۰ و Ready** شده است؛ مانع قدیمی pointer نسخهٔ ۱۹ در این دریافت دیگر وجود ندارد.

ثبت اصلاحات روی main از اتصال GitHub انجام می‌شود. توکن محلی GitHub پاسخ HTTP 401 می‌دهد و اتصال موجود ابزار workflow_dispatch ندارد؛ بنابراین انتشار سایت/HF/Kaggle از این محیط متوقف است و هیچ deploy یا نسخهٔ عمومی تازه ادعا نمی‌شود. هیچ DOI یا content release تازه ساخته نشده و نسخهٔ محتوا 1.3.4 است. Zenodo، DataCite و Wikidata در این تغییر دست‌کاری نشده‌اند. Freeze انجام نشده است.

پس از برقراری دسترسی اجرای workflow: ابتدا workflow موجود machine-readable-interop روی main و SHA نهایی با previous_website_commit=5e45873a95c63aa6206317d7f429d4d055f58f5c؛ سپس fetch عمومی و مقایسهٔ hash و ۶۰ رکورد/۴۷ متن اصلی/دو companion؛ سپس فقط یک اجرای platform-machine-readable-sync با pinهای دوباره بررسی‌شده (HF فعلی 96975d60… و Kaggle فعلی 20)، SHA سایت و run واقعی سایت. Zenodo metadata update برای این تغییر لازم نیست و باید false بماند. پیش از هر نوشتن، guard نسخه و revision موجود باید پاس شود.
